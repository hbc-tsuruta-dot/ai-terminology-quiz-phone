## 1. 目指す体験

「言葉を覚えるほど、学校から未知の世界へ進める」学習冒険ゲーム。高品質な背景、統一されたフレーム、短い戦闘演出、耳に心地よいSEを組み合わせる。問題文・解説を読む時間を最優先し、演出で学習を遮らない。

品質の判断軸は素材の数だけでなく、世界観の統一、反応の速さ、結果の分かりやすさ、飽きにくさ、音声操作の安定性とする。既存ゲームの画像・UIをコピーせず、独自の素材と構成で制作する。

既存の8段階、297語、授業5問・中間10問・期末20問、80%合格という学習構造を基盤にする。装飾や報酬で合格基準を変えない。

## 2. 美術方針：2.5Dの小さな冒険世界

リアルタイム3Dではなく、立体感のある描き下ろし画像を前景・中景・遠景に分けて配置する「2.5D」を採用する。遠景に空や建物、中景に舞台、前景に葉・机・魔法の粒子を置き、影と光で奥行きを作る。

- 背景：柔らかな光、絵本とゲーム背景の中間。SF機材と魔法の意匠を同じ世界に馴染ませる。
- キャラクター：既存の案内役を基本とし、会話時に小さく登場。問題文より目立たせない。
- 戦闘相手：人物ではなくモンスター。輪郭・質感・攻撃表現まで変え、色違いだけの増量を避ける。
- フレーム：石・木・金属・結晶の4系統。文字を置く中央は無地で、装飾は四隅と外周に集める。
- 文字：BIZ UDPゴシック。本文16px以上を基本に、明暗差を確保。画像に文字を焼き込まない。
- 色：通常は紺＋アイボリー＋青緑、試験は金、正解は青緑、不正解は落ち着いた赤。記号と文言も併用する。

## 3. 背景と舞台のバリエーション

完成版の目標は、学習背景16景（各段階2景）＋戦闘背景8景＝24景。空の色だけを変えたものは別景に数えない。初回制作は小学生段階の学習2景・戦闘1景に絞り、実画面で品質を確認してから横展開する。

| 段階 | 学習背景2景 | 戦闘背景 | 固有の小演出 |
|---|---|---|---|
| 小学生 | 朝の教室／夕方の校庭 | 学校の裏のひらめきの森 | 木漏れ日、葉、チョークの星 |
| 中学生 | 図書室／雨上がりの中庭 | 本の迷宮 | 紙片、灯り、開く本 |
| 高校生 | 放課後の実験室／屋上観測所 | 放電する実験ドーム | 小さな火花、星図 |
| 大学生 | キャンパス／研究図書館 | 知識競技場 | 紋章、観客席の光 |
| 一般 | 街のオフィス／夕暮れの都市 | データ運河の橋 | 情報の光、窓明かり |
| 大学教授 | 講義室／古い資料室 | 記憶の時計塔 | 時計の輪、浮かぶ図形 |
| AI学者 | AI研究所／結晶の実験室 | 演算の結晶洞窟 | 結晶の反射、光の線 |
| AI仙人 | 雲上の書庫／星空の庭 | 天界の知恵の祭壇 | 雲、星屑、光の輪 |

背景はセッション開始時に選び、回答中に切り替えない。同じ段階の直近2回と同じ組み合わせを避け、学習履歴をもとに未体験のものを優先する。背景には通常・試験・合格の照明状態を設ける。

## 4. 画面の設計

画面遷移は「ホーム → 授業／試験／戦闘 → 結果 → ホーム」。ホームから図鑑・実績・設定へも入れる。新しい演出を追加しても現在地と戻り先を常に明確にする。

| 画面 | 主な内容 | 演出と優先順位 |
|---|---|---|
| ホーム | 現在の段階、背景、学習進捗、授業・中間・期末 | 授業ボタンを最優先。イベントは小さな1枠 |
| 授業 | 問題、5択、解説、音声操作 | 背景は薄く。正誤は短い反応だけ |
| 試験 | 種別、問題数、進捗、回答 | 開始時に金のフレーム。回答中は静かにする |
| 戦闘 | 敵、舞台、両者の3点ゲージ、問題と5択 | 正解で攻撃、不正解で敵の反応。1問で1手 |
| 結果 | 点数、学んだ語、次にできること | 報酬は1枚の結果カードに集約 |
| 図鑑・実績 | 学習した用語、出会った敵、獲得装飾 | 未獲得項目にも入手条件を表示 |
| 設定 | SE・読み上げ音量、演出量、軽量表示 | テスト再生と初期値へ戻す操作 |

スマホ縦画面を基準にし、PCでは中央のゲーム画面と余白の背景で構成する。長い選択肢・大きな文字でも操作ボタンを隠さず、画面幅に応じて背景の高さを縮める。

## 5. 戦闘と短い演出

既存の3問先取を維持し、3点ゲージを盾・結晶として可視化する。反応速度は得点に含めず、音声利用者も同じ条件で遊べる。通常敵と試験後に挑めるボスで見た目を変える。

完成版の敵は16体（各段階の通常敵1体＋ボス1体）を目標にする。各体に待機・被弾・攻撃・敗北の4状態を用意。長編アニメーションではなく、静止画の切り替え、短い移動、発光で表現する。

| 発生条件 | 表現 | 標準時間・制約 |
|---|---|---|
| タップ | ボタンが少し沈む、短いクリックSE | 80〜120ms。直ちに入力を受け付ける |
| 正解 | ○表示、フレームの小発光 | 250〜400ms。解説をすぐ表示 |
| 戦闘で正解 | 光弾・斬撃・結晶のいずれか、敵の小反動 | 400〜650ms。ダメージ数値の乱舞は避ける |
| 戦闘で不正解 | 盾が1つ減る、敵が反応 | 250〜450ms。強い赤点滅・大音量を避ける |
| 3連続正解 | 小さな連続正解バッジ、追加の軽い音 | 350ms以下。能力補正は付けない |
| 勝利 | 敵の退場、報酬カード | 800ms以下、タップで短縮可能 |
| 進級 | 背景の扉が開く、次の舞台を見せる | 最大1.5秒、スキップ可、初回だけフル表示 |

正誤判定は最初の1回だけ確定。解説表示後のタップは次へ進む操作として扱い、同じタップで解説を飛ばさない。連打・音声完了・画面タップが重なっても二重遷移しない。画面を離れたら古い演出と予約済み音声を取り消す。

## 6. 飽きさせないイベント

時間制限や毎日のログイン義務ではなく、学習に意味のある変化を入れる。

- 「今日の5語」：未学習語と以前間違えた語の短い復習。翌日に取り逃した損失を作らない。
- 「発見した小道」：授業を3回完了するとホームに任意の背景イベントが1件出現。閉じても次回残る。
- 「知恵の挑戦状」：中間合格後に現れる任意の5問戦闘。参加しなくても進級できる。
- 「卒業記念」：各段階の期末初回合格でフレーム・称号を獲得。図鑑に記録。
- 「復習リベンジ」：間違えた語を後日正解できた時、小さな復習達成の演出。

モーダルイベントは結果画面で最大1件、装飾通知は1セッション最大2件。同じイベント文面を直近3回で繰り返さない。報酬は装飾・記録に限定し、ガチャ・課金通貨・学習の失敗ペナルティは初期仕様に含めない。

## 7. SE・音量・読み上げ

BGM、常時鳴る環境音、勝手に始まる音楽は使用しない。SEは操作と結果が伝わる短い音を用意する。

初期音源は14種：タップ、戻る、選択、正解、不正解、光弾、斬撃、結晶攻撃、敵の攻撃、連続正解、勝利、再挑戦、進級、報酬獲得。頻出するタップ・正解・攻撃には各2〜3の軽い音色差分を用意する。進級音も2秒以内のSEとする。

- 音量：SEと読み上げを別々に0〜100で設定。初期案はSE35、読み上げ80。これは相対音量であり実測音圧ではない。
- 全ミュート：SE・読み上げを両方停止し、音声認識も終了。解除してもマイクを自動再開しない。
- 音声中：読み上げ中の装飾SEは抑え、正誤SEが終わってから解説を読む。認識中はSEを再生しない。
- 同時発音：最大3音、連続タップ音は80ms以内の重複を抑制。正誤音を装飾音より優先する。
- 自動遷移：読み上げ正常終了後に1回だけ次へ。読み上げ失敗時は解説を画面に残して手動操作へ戻す。
- 保存：音量・ミュート・演出量は端末ごとに保持。音源未取得・再生制限があってもクイズは操作できる。
- 初回のユーザー操作で音声機能を準備し、バックグラウンド移行時は再生・認識を停止する。
- 制作時に音源間の聞こえ方とピークを揃え、使用許諾と入手元を台帳へ記録する。

## 8. 実装時の構造

採点・進級・学習履歴は既存Python／SQLiteを正とする。演出が失敗しても結果は失われない。演出側は確定済みの結果を受け取って表示する。

「回答 → 採点確定 → 表示・SE → 解説 → 次へ」の順序を共通化し、手動・音声で別々の進行処理を作らない。

- 舞台定義：段階ごとの背景、フレーム、敵、SEセット、出現条件。
- 演出制御：演出の優先順位、再生、スキップ、画面離脱時の中止。
- 音声制御：SE・読み上げ・認識の排他、音量、読み込み失敗の処理。
- 報酬・イベント：獲得履歴、発生済みイベント、重複受取防止。報酬はSQLiteへ保存。
- 設定：端末固有の音量、演出量、軽量表示。個別プレイヤー制は今回追加しない。

既存の大きなHTMLから、今回追加する演出・音声・舞台定義を独立ファイルに分ける。全アプリの作り直しは前提にしない。

## 9. 性能・操作・完成判定

以下は実装時の受入基準であり、現時点で達成済みという意味ではない。

- 幅360／390／430pxとPCで、横はみ出し・ボタン被りなし。主要操作領域48px以上。
- 背景・敵は現在の段階だけ読み込み、次の舞台は必要時に先読み。全24景を起動時に取得しない。
- 軽量表示では背景1枚・動きなし。端末の「視差効果を減らす」設定も尊重する。
- 開始時に必要な画像・SEの転送量は計3MB以内を目標に計測。10Mbps相当の回線で操作可能まで3秒以内を目標とする。
- 操作の視覚反応は100ms以内、演出中も次へ・戻るが効く。演出の標準は60fpsを目標にし、低性能端末では動きを減らす。
- 手動・音声で授業→中間→期末→進級を実機確認。連打、消音、画面離脱、再読み込み、音源失敗も確認する。
- 同じ試験結果を再送しても報酬が二重に増えない。再起動後も進級・実績を維持する。
- 既存の授業・試験・対戦テストを維持し、演出から学習データへの逆流を防ぐ。

## 10. 制作順と費用を抑える区切り

1. **共通基盤**：SE音量・ミュート、読み上げとの排他、演出量、入力の二重処理防止。
2. **小学生段階の完成見本**：学習背景2景＋戦闘1景、敵2体、基本フレーム、授業・試験・戦闘・結果の一通り。
3. **品質確認**：スマホで読みやすさ、音、テンポ、立体感を確認し、見本の方向を固定。
4. **8段階へ展開**：共通の定義形式で24景・敵16体・フレーム4系統へ拡張。
5. **イベントと収集**：復習イベント、卒業報酬、図鑑、実績を追加。

素材の大量制作は完成見本の確認後に行う。実装見積もりは工程ごとに提示し、画像生成回数と実機検証時間を別枠にする。今回は設計に限定し、制作費用・工数の確定値は出さない。
